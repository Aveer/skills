# Output formats

Choose the lightest format that answers the request.

## One-title fit check

Useful fields:

- **Predicted fit**
- **Confidence**
- **Dominant fit mechanisms**
- Short explanation
- Main risk
- **Best medium/platform/path**, when relevant

Do not force a numeric score if the evidence is too weak.

## Ranked recommendation table

Possible columns:

| # | Title | Fit | Confidence | Main mechanisms | Best path | Main risk |
|---|---|---:|---|---|---|---|

Use domain-specific columns only when they materially help the comparison.

## Large recommendation session

When useful:

1. short profile slice relevant to the request;
2. main ranking;
3. deeper explanations for top candidates;
4. optional category-specific mini-rankings;
5. practical shortlist of what to start now.

The practical shortlist should not automatically equal the top raw scores.
Balance fit, confidence, variety, friction, availability, and current context.

## Availability evidence

When regional/catalog availability matters, distinguish:

- confirmed for the user;
- official listing but entitlement/region uncertain;
- unverified.

Do not convert a global listing into a region-specific claim without evidence.

## Calibration update

When a user reports a new reaction:

- identify what it confirms or contradicts;
- separate foreground reason from incidental traits;
- mark provisional evidence as provisional;
- avoid broad rules from one title;
- update the profile only when the evidence is durable enough.
